# Feature: AK-krydser — duty/chore-cross tracking (internal area)

- **Feature ID:** F-009
- **Source file(s):** `application/controllers/intern/ak.php`,
  `application/models/aklog_model.php`, `application/models/akstatus_model.php`,
  `application/models/adminuser_model.php` (only `getAlumneOnId` used here),
  views `application/views/intern/ak.php`, `application/views/intern/adminAk.php`
- **URL / route:** (route `nyintern/(:any) → intern/$1`, so `nyintern/ak → intern/ak`; default action `index`)
  - `GET/POST /nyintern/ak[/]` — own personal AK log (`index` → `showPersonalLog(session alumne_id)`)
  - `GET/POST /nyintern/ak/showPersonalLog/{alumneId}[/success]` — a resident's AK log (own = editable; other = admin view)
  - `GET/POST /nyintern/ak/admin[/success]` — admin overview of all current residents' AK status
  - `GET /nyintern/ak/delete_log_element/{idOnElement}[/{backAlumneId}]` — delete one log row (admin)
  - `POST /nyintern/ak/showPersonalLog/{alumneId}` with `formname=updatestatus` — set a resident's status (admin; routed through `updatestatus`)
  - `POST /nyintern/ak/reduceAllKrydser` — bulk-reduce everyone's status, start new period (admin)
  - `submitkrydser` is **private** (no route) — invoked only from inside `showPersonalLog` on a POST to own log.
- **HTTP method(s):** GET + POST (forms post back to `showPersonalLog`, `admin`/`reduceAllKrydser`, and the GET delete link)
- **Access control:** logged-in (session `username`) for all actions; the `akRole` session flag
  (sourced from `gahk_admin_user.ak` at login — see `intern/admin.php:180`) gates everything except viewing/editing **one's own** log.
  Enforced **inline per action**, not centrally. ⚠ `akRole` is checked with `empty()`/`!empty()`, so any non-zero `ak` value grants admin AK rights.

## Purpose
Residents of the housing collective (GAHK) earn "AK-krydser" (penalty/duty crosses) for chores/work obligations.
Each resident sees their own running log of crosses and a current status total. An AK-officer (`akRole`) can
view any resident's log, add or delete crosses on their behalf, set an absolute status, see an overview of every
current resident, and at the start of a new duty period bulk-reduce everyone's status.

## Database interactions
- **Tables touched:** `intern_alumne_aklog` (R/W), `intern_alumne_akstatus` (R/W), `intern_alumne` (R, joins),
  `intern_alumne_liste` (R, current-month lookup). *(Correction: `ak` does **not** call `$this->counter()`, so it writes no `gahk_counter`/`gahk_counterdato` — see `99-index.md` §2.)*
- **Reads:**
  - `intern_alumne_aklog WHERE alumne_id = $alumneId ORDER BY id DESC` (`getLogByAlumneId`) — the per-resident log shown.
  - `intern_alumne_aklog WHERE id = $id` (`getElementById`) — single row, to learn its `alumne_id`/`krydser` before delete.
  - `intern_alumne_akstatus WHERE alumne_id = $alumneId` (`getStatusByAlumneId`) — current status total.
  - `SELECT COUNT(*) ... WHERE alumne_id = $alumneid` (existence checks in `increaseOrCreateStatus`/`updateOrCreateStatus`).
  - `getNewestMonthNumber()` — `SELECT DISTINCT monthNumber FROM intern_alumne_liste ORDER BY monthNumber DESC LIMIT 0,1`.
  - `getAll()` — joins `intern_alumne` LEFT JOIN `intern_alumne_akstatus` LEFT JOIN `intern_alumne_aklog`,
    filtered to residents present in `intern_alumne_liste` for the newest `monthNumber`,
    `GROUP BY tAl.ID`, `SUM(krydser) as krydserInLog`. Runs `SET SQL_BIG_SELECTS = 1` first.
  - `getAllSlackers()` — `intern_alumne_akstatus RIGHT JOIN intern_alumne ... WHERE ak.totalkrydser IS NULL`
    (residents with no status row). ⚠ The join uses `alumne.id` but the real column is `intern_alumne.ID` (see findings).
  - `Adminuser_model->getAlumneOnId($alumneId)` — `firstName,lastName,moveInDay FROM intern_alumne WHERE ID = $alumneId` (header for "other person").
- **Writes:**
  - **INSERT `intern_alumne_aklog`** — on add-to-log (`addAkLog`): `array_merge($_POST, {alumne_id, timestamp=time()})`.
    Real columns: `id, alumne_id, krydser, comment, timestamp`. ⚠ Whole `$_POST` merged in (mass-assignment).
  - **INSERT `intern_alumne_akstatus` `(alumne_id, totalkrydser=krydser)`** — `increaseOrCreateStatus` when no row exists.
  - **UPDATE `intern_alumne_akstatus` SET totalkrydser = totalkrydser + {krydser} WHERE alumne_id = $id** — `increaseOrCreateStatus` when row exists (add-to-log path).
  - **UPDATE `intern_alumne_akstatus` SET totalkrydser = {krydser} WHERE alumne_id = $id** — `updateOrCreateStatus` (set absolute, admin); INSERT if no row.
  - **UPDATE `intern_alumne_akstatus` SET totalkrydser = totalkrydser - {decValue} WHERE alumne_id = $id** — `decreaseStatus`, called on delete with the deleted row's `krydser`.
  - **DELETE `intern_alumne_aklog` WHERE id = {id}** — `deleteFromLog` (QB, escaped).
  - **`reduceAllKrydser` bulk op** (in order): (1) for each "slacker" from `getAllSlackers`, `addAlumneToTable($slacker->ID)` → INSERT `(alumne_id, totalkrydser=0)`; (2) `decreaseAllStatus($krydser)` → `UPDATE intern_alumne_akstatus SET totalkrydser = totalkrydser - {krydser}` (every row, no WHERE), then a second loop that intends to insert any current-month resident missing a status row but is **broken** (see Quirks).
  - *(No `gahk_counter`/`gahk_counterdato` write — this controller does not call `counter()`; correction per `99-index.md` §2.)*
- **Transactions / ordering:** none. All AK tables are **MyISAM → no transactions**. `reduceAllKrydser` performs
  N+1+M separate statements with no atomicity; a mid-run failure leaves partial state (some new rows added, some
  not, the global decrement applied or not). The add-to-log path does `increaseOrCreateStatus` **then** `addAkLog`
  as two independent statements; delete does `decreaseStatus` then `deleteFromLog` — neither pair is atomic.

## Business logic

**Auth/dispatch (showPersonalLog):**
```
if not username:            set redirect-after-login flashdata; redirect nyintern/admin
elif alumneId != session.alumne_id AND akRole empty:
                            redirect nyintern/ak        # cannot view others without akRole
else:
   if alumneId != session.alumne_id:                   # viewing someone else (akRole present)
        data.otherPerson = getAlumneOnId(alumneId)      # name header; NO add-form shown
   else:                                                # viewing own log
        submitkrydser(alumneId)                         # process any addtolog POST
   updatestatus(alumneId)                               # process any updatestatus POST (akRole only inside)
   data.aklog    = getLogByAlumneId(alumneId)
   data.akstatus = getStatusByAlumneId(alumneId)
   success = (uri segment 5 == "success")
   render intern/ak
```
Note: an AK-officer can edit a resident's status (via `updatestatus`) and delete log rows, but the **add-to-log
form is only rendered for one's own log** (view hides it when `otherPerson` is set) and `submitkrydser` is only
called on the own-log branch — so officers cannot *add* crosses to others through the UI, only set/delete.

**Add to log (submitkrydser, own log or akRole):**
```
if username == "":        redirect to login
elif akRole empty AND alumneId != session.alumne_id:   echo "Ingen adgang"   # (dead in practice: only called for own log)
elif POST.formname == "addtolog":
   validate krydser (natural, no zero) + comment (required)
   if valid:
      unset formname; $_POST = xss_clean($_POST)
      increaseOrCreateStatus(alumneId, $_POST)   # status += krydser (or create)
      addAkLog(alumneId, $_POST)                 # append log row
      redirect showPersonalLog/$alumneId/success
```

**Update status (updatestatus, akRole only):**
```
if username AND akRole not empty:
   if POST.formname == "updatestatus":
      validate krydser (integer — may be negative/zero)
      if valid:
         updateOrCreateStatus(backAlumneId, $_POST)   # SET totalkrydser = krydser (absolute)
         redirect showPersonalLog/$backAlumneId/success
```

**Delete log element (akRole only):**
```
if not username or akRole empty:  redirect login
else:
   el = getElementById(idOnElement)        # used raw [0]
   decreaseStatus(el.alumne_id, el.krydser)  # status -= that row's krydser
   deleteFromLog(idOnElement)
   redirect showPersonalLog/{backAlumneId or own}/success
```

**Bulk reduce / new period (reduceAllKrydser, akRole only):**
```
if username AND akRole not empty:
   validate krydser (natural, no zero); if invalid -> render admin()
   else:
      for slacker in getAllSlackers():        # residents with NULL status
          addAlumneToTable(slacker.ID)         # INSERT status row, totalkrydser = 0
      decreaseAllStatus(POST.krydser)          # UPDATE every row: totalkrydser -= krydser
      redirect /nyintern/ak/admin/success
```
`decreaseAllStatus` then runs a second block intended to insert any current-month resident still missing a status
row with `totalkrydser = -decValue`, hard-coded to `monthNumber = '24178'` — but it is doubly broken (see Quirks).

**Hard-coded monthNumber + negative-insert (`decreaseAllStatus`, `akstatus_model.php:83-103`):**
- The first statement `UPDATE intern_alumne_akstatus SET totalkrydser = totalkrydser - {decValue}` (no WHERE) **does work** — it reduces every existing status row.
- The follow-up SELECT looks for current-month residents not yet in `akstatus`, but filters on the **literal** `monthNumber = '24178'` instead of the dynamic newest month. `getAll()` uses the dynamic newest month; this function does not. So unless the live newest month happens to equal `24178`, this query returns the wrong set (likely empty/stale).
- Even when it returns rows, the insert is `$this->db->insert('intern_alumne_akstatus', -1*$inserData)` where `$inserData` is an **array**. `-1 * array` in PHP is a fatal `TypeError`/`Unsupported operand` (or in older PHP emits a warning and yields `0`/null), so the intended "insert with `-decValue` status" never inserts a valid row. The comment says it should insert these residents at `-decValue`; the code cannot. Net effect: residents who have **no** status row and are not caught by `getAllSlackers` earlier are simply skipped — but in practice `reduceAllKrydser` already inserted all `getAllSlackers` at `0` *before* calling `decreaseAllStatus`, so those `0` rows are then decremented to `-decValue` by the first UPDATE. The broken loop is effectively dead.

## Quirks, edge cases & suspected bugs
- ⚠ **Hard-coded `monthNumber = '24178'`** in `akstatus_model.php:95` — `decreaseAllStatus` uses a literal month instead of the newest month (which `getAll`/`getNewestMonthNumber` compute dynamically). Wrong/stale resident set; almost certainly a leftover test/placeholder value.
- ⚠ **`-1*$inserData` on an array** (`akstatus_model.php:100`) — `$inserData` is an associative array; multiplying it by `-1` is invalid in PHP. This insert never produces a valid row; the whole follow-up loop is effectively dead. Intended behavior (per comment) was to insert missing current-month residents at `-decValue`.
- ⚠ **`getAllSlackers` join references `alumne.id`** (`akstatus_model.php:107`) but the column is `intern_alumne.ID`. On MySQL this is case-insensitive for identifiers on most platforms so it likely works, but it is fragile and inconsistent with the rest of the codebase (`tAl.ID`).
- **`getElementById` returns an array, used as `[0]` with no empty-check** (`ak.php:133`) — deleting a non-existent id would error on `$elementToDelete[0]`.
- **`reduceAllKrydser` "clear the log" feature is disabled** — `adminAk.php:40-44` has a commented-out "Ryd loggen" checkbox; the help text promises the log is emptied, but no code deletes log rows. Status is reduced but the per-resident log is **never cleared**, contradicting the UI copy.
- **`increaseOrCreateStatus`/`updateOrCreateStatus` existence check uses `doesExist == "1"`** (string compare on COUNT) — works for exactly one row; if duplicate status rows ever existed (no unique constraint on `alumne_id`), the create branch would run and insert another duplicate.
- **`submitkrydser`'s `"Ingen adgang"` branch is dead** — it is only ever called on the own-log branch of `showPersonalLog`, so `alumneId == session.alumne_id` always there.
- **`index` ignores any success segment** and just forwards to `showPersonalLog`.
- **`reduceAllKrydser` redirects to `/nyintern/ak/admin/success` with a leading slash**; on validation failure it re-renders `admin()` rather than redirecting (so the URL stays `reduceAllKrydser`).
- All AK tables are `latin1` except `intern_alumne_liste` (`utf8mb3`); `comment` is `utf8mb3_bin` inside a `latin1` table — mojibake risk for Danish text in ETL.

## Reimplementation notes (Django)
- **Views:** a `DetailView`/`FormView` for personal log (own = editable, other = officer-only), an officer overview `ListView` (current-month residents), a delete action (POST, not GET), an update-status form, and a bulk-reduce action.
- **Forms:** explicit `krydser`/`comment` forms eliminate the mass-assignment and SQLi classes; ORM kills raw WHERE/UPDATE concatenation.
- **Models:** `AkLog` (`intern_alumne_aklog`), `AkStatus` (`intern_alumne_akstatus`, add `unique` on `alumne_id`), `AlumneListe` (`intern_alumne_liste`) for current-month membership.
- **FIX (record + confirm first):** the hard-coded `'24178'` month → dynamic newest month; the `-1*array` insert; decide whether "start new period" should actually clear the log (UI says yes, code doesn't). Move delete to POST + CSRF. Make `reduceAllKrydser` atomic (transaction).
- **PRESERVE:** the URL shapes (`/nyintern/ak`, `.../showPersonalLog/{id}`, `.../admin`, `.../reduceAllKrydser`), the role gate semantics (`ak` flag), and the add/set/delete workflow.
- **URL pattern:** keep `nyintern/ak/<method>[/<id>...]`.

## Open questions
- **Intent of `monthNumber = '24178'`**: was this ever a real month code, or a placeholder? Need the meaning of the `smallint monthNumber` encoding to choose the correct dynamic value (it should clearly be the newest month, matching `getAll`).
- **Intent of `-1*$inserData` / `-decValue` insert**: should new (statusless) current-month residents start a period at `-krydser`, at `0`, or be excluded? `reduceAllKrydser` already inserts slackers at `0` then decrements them; is the intended starting status `0` then `-krydser`, i.e. the same as everyone? Confirm desired semantics.
- **Should "start new period" clear the AK log?** The admin UI text and commented-out checkbox say yes; the code does not. Needs the AK-officers' confirmation before we "fix".
- **Should an AK-officer be able to *add* crosses to another resident?** Currently they can set/delete but the add form is own-log only — intended, or an oversight?
- **Bounds on status**: are negative totals meaningful (credit) or always a bug?
